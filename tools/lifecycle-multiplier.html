Lifecycle Campaign Multiplier

One brief becomes Email, SMS, WhatsApp and Push copy for every lifecycle segment — each one validated against the channel's real limits before it ever reaches your ESP.

The problem

A single campaign brief has to become copy for four channels across several lifecycle segments. Each channel has different hard limits, and they're the kind nobody remembers: SMS silently splits into two billed segments the moment you type a curly apostrophe, push bodies truncate mid-sentence on the lock screen, WhatsApp templates get rejected for a variable in the wrong place. So copy goes to upload, bounces back, and someone spends an afternoon counting characters by hand.

A message stays in the 7-bit GSM alphabet until one character falls outside it — a curly apostrophe, an em dash, an emoji — at which point the whole message switches to UCS-2 and the limit drops from 160 characters to 70. A single smart quote pasted from a doc can double your send cost. The counter below detects this and tells you which character did it.

How it works

The validation layer is deterministic and is the part that earns its keep. Generation is the easy half — and whether it comes from a template or from Claude, it goes through the same gate.

1
Brief once

Product, proof, objection, CTA and deadline become the variables every channel draws from, so the message stays consistent across them.

2
Expand

Each selected segment × channel produces three variants on different angles — value, reassurance, urgency — rather than three rewordings of the same sentence.

3
Encode & count

SMS is checked against the real GSM 03.38 alphabet, including the extension characters that cost two. Segment maths uses 160/153 for GSM-7 and 70/67 for UCS-2.

4
Validate

Length, truncation point, WhatsApp variable placement and subject-line preview width are all checked live, on every keystroke.

5
Sequence

Messages are spaced with a frequency cap, and a global audience triggers a quiet-hours warning rather than a silent 2am send.

6
Export clean

Failing variants are excluded by default, so the upload file cannot carry a message that would be rejected.

Without a key you get structured template variants — useful for testing the validator, obviously templated as copy. With a key, Claude writes them from your brief and the result is passed straight back through the same validator, so a model that blows the SMS limit gets flagged exactly like a human would. Your key stays in sessionStorage, goes only to api.anthropic.com, and is dropped when the tab closes.
